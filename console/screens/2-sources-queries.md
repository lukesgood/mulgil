# 2. 소스·쿼리 (Sources & queries)

> Phase 2a — 엔진 중심 제품의 첫 운영 화면. **읽기 전용. SQL 실행 기능 없음.**

## 목적
엔진에 무엇이 연결되어 있고(소스 카탈로그·랜딩존·저장소 백엔드), 그 연결이 건강한지,
어떤 쿼리가 어떤 리소스 그룹에서 얼마나 돌았는지 본다. 등급 B의 핵심 운영 질문
"소스 시스템에 부담을 주고 있는가"에 답하는 화면.

## 데이터
- `GET /sources` — 카탈로그: 이름, 커넥터 종류, 등급(A 랜딩존 / B 소스), 연결 상태(마지막 성공 메타데이터 조회), 읽기 전용 계정 여부, 읽기 복제본 여부, 등록된 테이블 수, Sumun 정책에서 허용된 키 수
- `GET /sources/{id}/load` — 최근 24h/7d 쿼리 수, p50/p95 실행 시간, 동시 실행 최대, 소스 커넥션 수(exporter 있을 때), 거부·타임아웃 수
- `GET /queries` — 쿼리 이력(Trino 이벤트 리스너 / Trino Gateway): 시각, 호출자(Sumun 호출자 id, 가명화), 리소스 그룹, 소스 카탈로그, 상태, 실행 시간, CPU ms, 스캔 바이트, 거부 사유(있으면). **쿼리 텍스트는 표시하지 않음** — 정책·PII 노출 방지; Sumun 감사 id만 링크
- `GET /engine/resource-groups` — governed/federated/maintenance 사용률, 큐 길이, 거부 수
- `GET /storage/summary`, `/storage/nodes` — 랜딩존 저장소 백엔드(S3 호환 아무 것): 버킷 용량·추이·소진 예상일; SeaweedFS(옵션 A)일 때만 노드·복제 상태 탭 활성

## 화면 구성
1. **연결 표** — 카탈로그별 상태 점, 등급 배지, 계정 유형(읽기 전용/복제본), 테이블 수, 허용 키 수. 행 클릭 → 드로어
2. **소스 드로어** — 부하 지표 그래프(24h/7d), 커넥터 기본값(pushdown·max-splits·timeout) 읽기, "이 소스를 랜딩존으로 적재" 안내 링크(반복 부하 시)
3. **리소스 그룹 게이지** — 세 그룹의 동시성·CPU 사용률, 큐
4. **쿼리 이력 표** — 필터: 기간, 호출자, 리소스 그룹, 소스, 상태. 쿼리 텍스트 없음
5. **저장소 백엔드 탭** — 랜딩존 미설치면 숨김. SeaweedFS면 노드·복제 추가 탭

## 동작
없음. 카탈로그 추가·변경은 Helm values/BOM 변경(릴리스 절차), 정책은 Sumun 콘솔 — 모두 링크.

## 빈 상태·오류
- 소스 0개: "소스 카탈로그 템플릿으로 첫 연결 — `engine/catalogs/`" 안내
- 이벤트 리스너 미설정: 쿼리 이력 대신 배너, 나머지 정상
- 소스 exporter 없음: 커넥션 수 "—", Trino 측 지표만

## 인수 기준
- [ ] 7종 템플릿 중 하나로 연결한 PostgreSQL이 등급 B·읽기 전용으로 표에 뜬다
- [ ] 소스에 동시 쿼리 6개를 던지면 `federated` 그룹에서 2개가 큐에 들어가고 게이지에 보인다
- [ ] 쿼리 이력 어디에도 SQL 텍스트·PII가 나타나지 않는다(테스트: 주민번호 리터럴 포함 쿼리)
- [ ] 랜딩존 미설치 환경에서 저장소 탭이 보이지 않는다
