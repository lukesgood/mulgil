# 7. 거버넌스 (Governance) — Sumun 읽기 전용 뷰

> Phase 3. Sumun `GET /usage/export`가 먼저 있어야 한다.

## 목적
플랫폼 운영자가 "누가 데이터를 얼마나 쓰고 있고 마스킹이 걸리고 있는가"를
콘솔을 떠나지 않고 본다. 정책·키·예산 변경은 하지 않는다 — Sumun 콘솔 링크.
Sumun 단독 고객(세그먼트 A)에게는 이 화면이 없다.

## 데이터 (Sumun 집계 API `GET /usage/export` — sumun ADR 0003)

ops는 Sumun의 데이터베이스에 접속하지 않는다. Sumun이 가명화·집계를 마친
결과만 받는다. 망분리 환경에서는 ops → Sumun API 경로 하나만 열면 된다.
- `GET /governance/callers` — 호출자(에이전트·서비스 계정): 이름, 종류, 허용 범위 요약(컬렉션 n, 테이블 n), 예산 한도·소진율, 상태(active/budget_exhausted/rate_limited), 마지막 호출.
- `GET /governance/usage?from&to` — 호출자별·도구별(`search`/`rag`/`sql`/`query_metric`) 호출 수, 거부 수(402/429/403 분리), 마스킹 적용 건수, 스캔 바이트, 토큰.
- 테이블별 접근: 어느 호출자가 어느 Gold 테이블을 읽었는지(테이블 화면 상세에서도 참조).

## 화면 구성
1. **헤더** — 기간, 총 호출, 거부율, 마스킹 적용 비율, 예산 소진 호출자 수. Sumun 콘솔 링크 버튼.
2. **호출자 표** — 상태 배지, 예산 바, 호출 수, 거부 수, 비용(비용 화면과 동일 수치). 행 클릭 → 드로어.
3. **호출자 드로어** — 도구별 호출 추이, 거부 사유 분포(402/429/403), 접근한 테이블·컬렉션 목록, 최근 호출 20건 요약(Sumun이 가명화·집계한 값). "Sumun에서 열기" 링크.
4. **테이블 × 호출자 매트릭스** — Gold 테이블 행, 호출자 열, 셀 = 호출 수. PII 컬럼 포함 테이블은 행에 표시.
5. **거부 추이** — 402/429/403 일별 막대. 403 급증은 스코프 설정 오류 신호로 설명 문구.

## 동작
없음. 모든 변경 버튼은 Sumun 콘솔 딥링크(`/callers/{id}`, `/budgets`).

## 빈 상태·오류
- Sumun 미설치(세그먼트 A 아님, 설치 선택 안 함): 메뉴에서 화면 숨김.
- Sumun API 불가: "Sumun에 연결할 수 없습니다 — ops의 Sumun 서비스 계정과 네트워크 경로 확인" + 가이드 링크.
- 감사 행 0건: "아직 호출이 없습니다" + MCP 첫 호출 안내.

## 인수 기준
- [ ] Sumun 테스트 호출 100건(마스킹 30건, 402 5건) 후 헤더 수치가 정확히 일치한다.
- [ ] ops가 쓰는 Sumun 서비스 계정은 `usage:read` 스코프만 가지며, 다른 Sumun API 호출 시 403.
- [ ] 호출자별 비용이 비용 화면 by-caller와 동일하다.
- [ ] 감사 행의 subject 원문이 어디에도 노출되지 않는다(가명화 값만).
