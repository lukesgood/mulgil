# 5. 스토리지 (Storage)

## 목적
용량이 언제 차는지, 복제가 깨진 곳이 있는지, 어느 버킷이 자라는지 본다.
노드·디스크 교체 절차는 인프라 가이드와 `weed shell`이 맡고, 이 화면은 보기만 한다.

## 데이터
- `GET /storage/summary` — 총 용량·사용·여유, 7/30/90일 추이와 소진 예상일(선형 외삽), 버킷별 사용량(lakehouse/landing/raw/exchange/audit 등), 복제 상태(`under_replicated_volumes`, `read_only_volumes`), 마스터 리더.
- `GET /storage/nodes` — 노드별: 호스트, 랙, 상태, 디스크별 사용률, 볼륨 수, 마지막 하트비트. aws 프로파일은 노드 대신 S3 스토리지 클래스별 바이트.
- `GET /metrics/query` — 디스크 사용률, IOPS, 네트워크 시계열.

## 화면 구성 (sovereign)
1. **용량 헤더** — 사용률 게이지, 소진 예상일("현재 추세로 2027-03-14"), 85/90% 임계선.
2. **버킷 표** — 이름, 용도, 바이트, 객체 수, 30일 증가율, 복제 설정(`010` 등). audit 버킷은 Object Lock 상태 표시.
3. **복제 상태** — 복제 부족 볼륨 수(0이면 녹색), 읽기 전용 볼륨, 리더 노드. 0이 아니면 `volume.fix.replication` 안내 문구와 가이드 링크.
4. **노드·랙 격자** — 랙 열, 노드 카드(디스크별 바 차트, 상태). 하트비트 끊긴 노드 회색.
5. **추이 그래프** — 전체·버킷별 선택, 7/30/90일.

aws 프로파일: 1·2·5만 표시, 3·4 대신 S3 스토리지 클래스 구성과 S3 Tables 유지보수 상태.

## 동작
없음(읽기 전용). 노드 카드의 "가이드" 링크 → docs/guide 장애 대응 절.

## 빈 상태·오류
- SeaweedFS master API 불가: Prometheus 데이터로 용량·추이만 표시, 복제·노드는 "—"와 배너.
- 추이 데이터 7일 미만: 소진 예상일 대신 "추이 수집 중 (n일)".

## 인수 기준
- [ ] 볼륨 노드 하나를 내리면 5분 내 복제 부족 수가 0 이상으로 바뀌고 카드가 회색이 된다.
- [ ] 버킷 표의 합계가 용량 헤더의 사용량과 일치한다(복제 포함/미포함을 라벨로 구분).
- [ ] 소진 예상일이 30일 추세와 ±3일 이내로 일치한다(합성 데이터 테스트).
